ช่องว่างการจัดการ & คุณภาพข้อมูล
(Data Management & Quality Gaps)
ไม่มี Data Dictionary / Data Definition กลางที่ใช้ร่วมกันทุกกอง — นิยามข้อมูลต่างกันระหว่าง กวบ./ศสท./สรข.
ข้อมูลซ้ำซ้อน (Redundancy) เช่น ข้อมูลประทานบัตรถูกบันทึกทั้งในกระดาษ Excel และระบบฐานข้อมูล
ขาดมาตรฐาน Data Quality (ความครบถ้วน ความถูกต้อง ความเป็นปัจจุบัน) — ยังไม่มี KPI คุณภาพข้อมูล
ไม่มีกระบวนการ Data Lifecycle อย่างเป็นทางการ — ไม่ชัดเจนว่าข้อมูลใดควรเก็บ/ทำลาย/เก็บถาวร
ขาด Data Owner / Data Steward ที่ชัดเจนในแต่ละชุดข้อมูล
ข้อมูลจาก สรข. 8 เขต มาในรูปแบบที่ไม่มาตรฐาน — ยากต่อการรวมศูนย์
🏗
ช่องว่างเทคโนโลยี & สถาปัตยกรรม
(Technology & Architecture Gaps)
ไม่มี Data Architecture ระดับองค์กร — แต่ละระบบ (GIS, e-Mining, EIA) ถูกสร้างแยกส่วน ไม่ interconnect
ขาด API มาตรฐานสำหรับเชื่อมระหว่าง สอจ. (ปก.อก.) กับ สรข./กพร. — ข้อมูลต้องส่งผ่านหนังสือราชการ
ไม่มี Data Catalog หรือ Metadata Repository กลาง — ไม่รู้ว่ามีข้อมูลอะไรอยู่ที่ไหนบ้าง
ระบบฐานข้อมูลหลายระบบ ไม่มี Master Data Management (MDM) — ข้อมูลเดียวกันต่างกันในแต่ละระบบ
ยังไม่มี Data Pipeline อัตโนมัติ — Dashboard ทำจาก Export ด้วยมือ ไม่ real-time
Infrastructure ไม่รองรับ Big Data / AI Analytics ในอนาคต
⚖
ช่องว่างด้านกฎหมาย & การปฏิบัติ
(Legal & Compliance Gaps)
พ.ร.บ. แร่ 2560 กำหนดให้ประทานบัตรเป็นกระดาษ — แต่ไม่มีแนวปฏิบัติการจัดการข้อมูลดิจิทัลคู่ขนาน
PDPA 2562 มีผล แต่กพร. ยังไม่มี Data Classification Standard ชัดเจน ว่าข้อมูลใดเป็น PII
พ.ร.บ. รัฐบาลดิจิทัล 2562 กำหนดให้เชื่อมข้อมูลรัฐ — แต่ยังไม่มี Interoperability Standard กับหน่วยงานอื่น
ยังไม่มีนโยบาย Data Retention & Disposal ที่สอดคล้องกับกฎหมาย
กรอบ DG Framework (สพร.) ยังไม่ถูก implement — มีเฉพาะในรูปแบบเอกสาร ไม่ได้ปฏิบัติจริง
👥
ช่องว่างด้านคน & กระบวนการ
(People & Process Gaps)
ไม่มีโครงสร้าง Data Governance Council / คณะกรรมการกำกับดูแลข้อมูลอย่างเป็นทางการ
ยังไม่มีตำแหน่ง CDO / Data Steward / Data Owner ที่ถูก assign อย่างชัดเจน
บุคลากรขาดความรู้ด้าน Data Governance — ยังไม่มีการอบรมหรือ awareness program
กระบวนการทำงานยังเป็น manual — ขาด SOP ที่ระบุว่าข้อมูลไหล/ตรวจ/อนุมัติอย่างไร
การสื่อสารระหว่างหน่วยงาน (สอจ.–สรข.–กวบ.–ศสท.) ยังไม่มีช่องทางแลกเปลี่ยนข้อมูลมาตรฐาน
⚖ ช่องว่างกฎหมาย — มีกำหนดในกฎหมาย แต่ยังขาดการนำไปปฏิบัติจริง
พ.ร.บ. แร่ 2560 — บังคับกระดาษ แต่ไม่ห้ามมีระบบดิจิทัลคู่ขนาน → ต้องออกแบบ Hybrid Model
PDPA 2562 — ต้องมี Data Classification + Consent Management แต่ยังไม่มี Policy
พ.ร.บ. ดิจิทัล 2562 — บังคับเชื่อมข้อมูล แต่ยังไม่มี API / Interoperability กับ สอจ./กพส.
พ.ร.บ. ข้อมูลข่าวสาร 2540 — กำหนดสิ่งที่ต้องเปิดเผย แต่ยังไม่มี Open Data Policy ชัดเจน
พ.ร.บ. ไซเบอร์ 2562 — ต้องมี Data Security Policy แต่ยังไม่มีมาตรฐานความปลอดภัยข้อมูล
กรอบ DGA / สพร. — มีคู่มือ DG Framework แต่ กพร. ยังไม่ได้ adopt อย่างเป็นทางการ

งวด 3
สถาปัตยกรรมข้อมูล (Data Architecture)
ส่งมอบภายในวันที่ 150 · 30% ของวงเงิน
A1
คัดเลือกกระบวนงานสำคัญ 1 กระบวนงาน — แนะนำให้เลือก "การขอและออกประทานบัตร" เพราะมีข้อมูลหลายประเภท หลายหน่วยงาน และ business impact สูงที่สุด
A2
จัดทำ Enterprise Data Model ระดับ Conceptual — แสดงความสัมพันธ์ระหว่าง Entity หลัก: ผู้ประกอบการ / แหล่งแร่ / ใบอนุญาต / พื้นที่ GIS / EIA / ค่าภาคหลวง
A3
วาด Data Flow Diagram (DFD) ของกระบวนงานที่เลือก — ระบุให้ชัดว่าข้อมูลแต่ละประเภทไหลจากไหนไปไหน ใครสร้าง ใครใช้ ระบบใดรับ
A4
กำหนด Data Life Cycle อย่างเป็นทางการ — สร้าง → ตรวจสอบ → อนุมัติ → ใช้งาน → เก็บถาวร → ทำลาย พร้อมระยะเวลาตาม พ.ร.บ. แร่
A5
ออกแบบ Logical Data Architecture ที่รองรับ Hybrid (กระดาษ+ดิจิทัล) — ระบุจุดเชื่อมต่อ API ระหว่าง i-Single Form / e-Mining / GIS / EIA / สอจ.
A6
จัดทำ Data Catalog + Metadata Repository เบื้องต้น ครอบคลุมชุดข้อมูลสำคัญ ≥ 20 ชุดแรก พร้อม Data Dictionary ภาษาไทย
A7
กำหนด Data Classification Standard ระดับแรก — แบ่ง: สาธารณะ / ภายในองค์กร / ลับ (PII/ค่าภาคหลวง) / ลับมาก สอดคล้อง PDPA
งวด 4
กรอบธรรมาภิบาลข้อมูล (Data Governance)
ส่งมอบภายในวันที่ 240 · 25% ของวงเงิน
G1
จัดทำ DG Framework ตาม สพร. 3 องค์ประกอบ — (1) Definition & Rules (2) DG Structure (3) DG Process — โดยอ้างอิงบริบทแร่ธาตุเฉพาะ กพร.
G2
ออกแบบ Data Policy ฉบับแรก (9 นโยบาย) ตาม TOR ข้อ 4.11 — ครอบคลุม: Data Policy / Classification / Exchange / PII / Security / Quality / Open Data / Innovation / Assessment
G3
กำหนด Data Exchange Standard กับหน่วยงานพันธมิตร — สพร. / กพส. / สผ. / กรมทรัพยากรธรณี / i-Industry (ปก.อก.) — ออกแบบ API Schema มาตรฐาน
G4
วางโครงสร้าง DGC และ Role ทุกระดับ — กำหนด RACI Matrix: ใครรับผิดชอบ ใครรับทราบ ใครให้ความเห็นชอบ สำหรับข้อมูลแต่ละประเภท
G5
ออกแบบ Data Quality KPI และกระบวนการตรวจสอบ — วัดความครบถ้วน ถูกต้อง ทันสมัย สม่ำเสมอ รายงานอัตโนมัติผ่าน Dashboard ศสท.
G6
จัดทำ Compliance Mapping — เชื่อม DG Policy กับ พ.ร.บ. แต่ละฉบับ แสดงให้เห็นชัดว่า Policy ใดตอบสนองกฎหมายใด
G7
จัดฝึกอบรม ≥ 100 คน — แบ่งเป็น 3 กลุ่ม: ผู้บริหาร (นโยบาย) / เจ้าหน้าที่ IT (ระบบ) / เจ้าหน้าที่สาย กพร.-สรข. (ปฏิบัติ) รูปแบบออนไลน์
